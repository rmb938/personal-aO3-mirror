# personal-aO3-mirror
Personal Local Mirror for AO3 - https://archiveofourown.org/

## AI Disclaimer

This project's code was developed with the help of AI.

No AI was used to scrape, read, or view any works from AO3. The scraper is ordinary Go code
with no AI or machine-learning components, and nothing it collects is used for AI training.

During development the AI assistant is mechanically blocked from fanwork content: it cannot
read the mirrored data, query the databases, or fetch AO3 pages. Parsers are built from AO3's
open-source code ([otwcode/otwarchive](https://github.com/otwcode/otwarchive)) and synthetic,
hand-written test fixtures. See [`CLAUDE.md`](CLAUDE.md) and
[`.claude/hooks/guard.py`](.claude/hooks/guard.py) for the rules and their enforcement.

## Parser skeletons

`testdata/skeletons/*.skel.html` are structure-only copies of real AO3 pages, used to check the
parsers against the live site's HTML. They are generated by `cmd/skeletonize`, which replaces
all text, names and values with consistent placeholders (lorem ipsum words, random numbers and
dates; AO3's own interface labels are kept). Work text, summaries and notes collapse to a single
placeholder. Skeletons contain no fanwork content, which is what makes them safe to commit and to
share with the AI assistant. `testdata/fixtures/*.html` are different: those are hand-written
synthetic pages.

Regenerate skeletons when AO3 changes its HTML or a parser reports `parse_unexpected`:

1. Set up the local config (`contact.discord` is required; it is sent in the User-Agent):
   ```
   cp ao3mirror.example.yaml ao3mirror.local.yaml   # then set contact.discord
   ```
2. Get each page, either directly from AO3 (polite: User-Agent, robots.txt, pacing, retries):
   ```
   go run ./cmd/skeletonize --config ao3mirror.local.yaml -o testdata/skeletons/work-chaptered.skel.html https://archiveofourown.org/works/<id>
   ```
   or, if AO3 is rejecting non-browser clients (e.g. Cloudflare 525s during an incident), save
   the page from your browser (Ctrl+S, "Web Page, HTML only") into `data/skeleton-input/` and run:
   ```
   for n in work-chaptered work-oneshot listing-tag series; do
     go run ./cmd/skeletonize data/skeleton-input/$n.html -o testdata/skeletons/$n.skel.html
   done
   ```
   Pages to use (any public ones):

   | File | Page |
   |---|---|
   | `work-chaptered.skel.html` | a work with more than one chapter, `/works/<id>?view_full_work=true` |
   | `work-oneshot.skel.html` | a single-chapter work (Chapters `1/1`), `/works/<id>` |
   | `listing-tag.skel.html` | a tag listing past page 1, `/tags/<tag>/works?page=2` |
   | `series.skel.html` | a series page, `/series/<id>` |

   The file name prefix (`work`, `listing`, `series`) tells the tests which parser to check.
3. Check the parsers against them:
   ```
   go test ./internal/parse -run Skeleton -v
   ```

`data/` is gitignored and never read by the AI assistant; delete `data/skeleton-input/` once the
skeletons are generated if you like.
