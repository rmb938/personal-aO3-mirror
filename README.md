# personal-aO3-mirror
Personal Local Mirror for AO3 - https://archiveofourown.org/

## AI Disclaimer

This project's code was developed with the help of AI.

No AI was used to scrape, read, or view any works from AO3. The scraper is ordinary Go code
with no AI or machine-learning components, and nothing it collects is used for AI training.

During development the AI assistant is mechanically blocked from fanwork content: it cannot
read the mirrored data, query the databases, or fetch AO3 pages. Parsers are built from AO3's
open-source code ([otwcode/otwarchive](https://github.com/otwcode/otwarchive)) and synthetic,
hand-written test fixtures. See [`CLAUDE.md`](CLAUDE.md) and
[`.claude/hooks/guard.py`](.claude/hooks/guard.py) for the rules and their enforcement.

## Data at rest

The mirrored works in `data/` are stored unencrypted (search needs them in the clear). If you
mirror works that aren't public any more (restricted to logged-in users, or since deleted by
their authors), keep `data/` and its backups on an encrypted disk (LUKS, FileVault, BitLocker).

## Backing up accounts

Accounts live in `users.db` in the admin socket's directory (`data/api/` by default), and every
secret in it (password hashes, TOTP secrets, recovery codes, token signing keys) is encrypted
under master keys kept beside it in `keys.db`.
The two only work as a pair: users.db without its keys.db can't log anyone in, and every
account then needs an admin reset link.

With `ao3mirror serve` running, `ao3mirror backup DIR` writes a consistent copy of both into
`DIR`, a new directory (mode 0700, files 0600). Serve pauses master key rotation while it
copies, so the pair always matches.

- **Contents:** users.db and keys.db only. The mirror itself (`meta.db`, `content.db`,
  images) is not included: copy `data/` with `run` and `serve` stopped for that.
- **Sensitivity:** a backup is as sensitive as the live files. Keep it private and on an
  encrypted disk. Keeping both files together decrypts every stored secret.
- **Retention:** serve deletes a retired master key 7 days after rotation, but a backup keeps
  its keys for as long as the backup exists. Delete old backups when you no longer need them.
- **Restore:** stop `serve`, copy both files from the backup into that directory (keep them
  0600, and delete any `users.db-wal` and `users.db-shm` left there) and start `serve`. On startup it checks that every value in users.db is under a key in
  keys.db, and refuses to start on a mismatched pair.

## Parser skeletons

`testdata/skeletons/*.skel.html` are structure-only copies of real AO3 pages, used to check the
parsers against the live site's HTML. They are generated by `cmd/skeletonize`, which replaces
all text, names and values with consistent placeholders (lorem ipsum words, random numbers and
dates; AO3's own interface labels are kept). Work text, summaries and notes collapse to a single
placeholder. Skeletons contain no fanwork content, which is what makes them safe to commit and to
share with the AI assistant. `testdata/fixtures/*.html` are different: those are hand-written
synthetic pages.

Regenerate skeletons when AO3 changes its HTML or a parser reports `parse_unexpected`:

1. Set up the local config (`contact.discord` is required; it is sent in the User-Agent):
   ```
   cp ao3mirror.example.yaml ao3mirror.local.yaml   # then set contact.discord
   ```
2. Get each page, either directly from AO3 (polite: User-Agent, robots.txt, pacing, retries):
   ```
   go run ./cmd/skeletonize --config ao3mirror.local.yaml -o testdata/skeletons/work-chaptered.skel.html "https://archiveofourown.org/works/<multi-chapter id>"
   go run ./cmd/skeletonize --config ao3mirror.local.yaml -o testdata/skeletons/work-oneshot.skel.html "https://archiveofourown.org/works/<single-chapter id>"
   go run ./cmd/skeletonize --config ao3mirror.local.yaml -o testdata/skeletons/listing-tag.skel.html "https://archiveofourown.org/tags/<tag>/works?page=2"
   go run ./cmd/skeletonize --config ao3mirror.local.yaml -o testdata/skeletons/series.skel.html "https://archiveofourown.org/series/<id>"
   go run ./cmd/skeletonize --config ao3mirror.local.yaml -o testdata/skeletons/tag-character.skel.html "https://archiveofourown.org/tags/<character tag>"
   ```
   Work URLs get `?view_full_work=true` added automatically. Each command retries for up to
   ~15 minutes if AO3 returns errors (`--retry N` to change).
   or, if AO3 is rejecting non-browser clients (e.g. Cloudflare 525s during an incident), save
   the page from your browser (Ctrl+S, "Web Page, HTML only") into `data/skeleton-input/` and run:
   ```
   for n in work-chaptered work-oneshot listing-tag series tag-character; do
     go run ./cmd/skeletonize data/skeleton-input/$n.html -o testdata/skeletons/$n.skel.html
   done
   ```
   Pages to use (any public ones):

   | File | Page |
   |---|---|
   | `work-chaptered.skel.html` | a work with more than one chapter, `/works/<id>?view_full_work=true` |
   | `work-oneshot.skel.html` | a single-chapter work (Chapters `1/1`), `/works/<id>` |
   | `listing-tag.skel.html` | a tag listing past page 1, `/tags/<tag>/works?page=2` |
   | `series.skel.html` | a series page, `/series/<id>` |
   | `tag-character.skel.html` | a canonical character tag's own page, `/tags/<tag>` (not `/works`) |

   The file name prefix (`work`, `listing`, `series`, `tag`) tells the tests which parser to check.
3. Check the parsers against them:
   ```
   go test ./internal/parse -run Skeleton -v
   ```

`data/` is gitignored and never read by the AI assistant; delete `data/skeleton-input/` once the
skeletons are generated if you like.
